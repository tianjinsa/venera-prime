### 阅读器进入与退出

- 使用独立测试应用中的 32 张程序绘制图片（2048×3072）建立基线：依次跳到第 4/8/12/16/20/24 页，退出后再进入 4 次。未复现秒级卡顿。
- 修改前：解码缓存最高 288 MiB，退出时立即降到 96 MiB；缓存上限在 300/100 MiB 间切换。进入/翻页/退出段最慢 UI 构建 15.811 ms、绘制 4.274 ms；重复进入段分别为 8.090/2.435 ms。报告：`.dart_tool/history-performance/reader-before-device-performance.json`。
- Windows 回归测试原先的 PNG 无法解码，且真实文件读取未正确等待；旧代码同样在清理文件时失败。现已更换有效图片并等待预加载，验证真实图片显示后的快速拖动、边缘滚动、后台/退出前最后进度立即写入 SQLite，以及退出后无延迟历史通知。
- 阅读缓存、上述交互、历史数据库和阅读统计：14 项测试通过；相关 8 个文件静态检查通过。
- 修改后同一真机脚本通过：解码缓存峰值 192 MiB，退出时不再立即缩减。进入/翻页/退出段 26 帧，最慢 UI 构建 21.072 ms、绘制 8.270 ms；重复进入段 35 帧，最慢 UI 构建 6.959 ms、绘制 2.621 ms，退出采样均无 live/pending 图片。报告：`.dart_tool/history-performance/reader-after-device-performance.json`。
- 缓存上限现在按可用内存的 1/16 估算，限制在 32–192 MiB；系统内存压力通知将其限制到 32 MiB 并暂停主动预解码。退出延迟 1 秒收缩缓存，快速重新进入可取消收缩；晚到的内存查询不会覆盖新阅读会话。
- 结论边界：本次证实缓存占用上限下降和进度/控制器生命周期正确；首次进入的最慢帧未改善，不能声称原设备内存紧张时的秒级卡顿已消除。保留等待后翻页和内存压力验证到任务 5。缓存字节数不等同于进程 RSS 或 GPU 实际占用。
